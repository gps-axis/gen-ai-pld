PLD Harness

A garment off the wall, laid flat, in one command.

The harness takes a phone photo of a pinned, creased garment and a real laydown shot of a similar product, then lets a model iterate with an image editor until the garment sits in the reference's lay. It measures every attempt, refuses to ship anything it did not generate untouched, and stops before spending money when the inputs are not good enough.

$ ./run.sh --style 671304002 --item-details "GAP MENS MENS KNITS L/S KNITS" \ --source inputs/off_set_image.jpg --max-images 10 --yolo \ --task "make the off_set_image.jpg look like the reference_greyscale shape"
The whole run

One command, four stages, two places it may stop for free.

run.sh signs in to the DAM, pulls the reference candidates, then hands everything to the harness. The harness cleans the source, chooses the reference, and only then lets the model start spending images.

run.sh

Sign in, then pull the references

Checks the saved DAM session and signs in from the terminal when it has expired. Downloads the style's laydown shots into the shared library, verifies by filename that every JPG the manifest lists is there, then starts the harness under one session stamp so the whole run lives in one folder.

step 0

Segment the source, never judge the raw photo

The segmenter drops the wall and its shadow and stands the garment on a white plate. Notches left by hanger clips in the top edge are closed with fabric from either side, so the generator sees an unbroken waistband instead of a bite to copy. A damaged result stops the run with exit 21.

search

Choose the reference from the library

A vision model describes the segmented source and every library image, then scores each candidate on garment type, lay, and tone. Colour weighs half, tone four times more. The best candidate must reach 78; the winner is desaturated into reference_greyscale.jpg, because it is a shape reference and never a colour target.

loop

Let the model work towards the reference

Turn 1 pins both images into the conversation. From there every tool is available on every turn: edit the prompt section by section, generate one or two images, segment a candidate, measure, compare, take notes. Each new candidate arrives with its numbers underneath, so the model sees what it bought without spending a turn asking.

ship

Deliver the best four, untouched

pick_best names up to four candidates exactly as fal.ai returned them. A segmented or polished file is refused. Empty slots are filled by the harness from its own lay ranking, and picks.json says which were the model's and which were filled. finish closes with an honest status.

Where the reference comes from

A style number first, free text when the number has nothing.

The DAM is searched inside the Gap folder with the view's standing filters: laydown shot type and FINAL production status. Every pull is recorded in its own manifest, so a repeat run comes back from the zip without touching the network.

P01, AV5, AV2
Shot request codes. P01 and AV5 are the laydown angles worth having; a style with neither yields every code it does have, capped per code.
Already complete
A manifest written under the current cap is reused. One written under a smaller cap is fetched again, unless it already took every shot the DAM had.
Restored N JPG files
The library was emptied since the last pull; the JPGs come back from the saved zip, no network.
no laydown assets
The style search came back empty. The DAM search is case-sensitive: Hoodie returned 313 laydowns, hoodie none.
Applied Filters popup
Opens over the first asset card when the filter panel is pinned open. The scraper closes it before selecting, or every click is intercepted.
bundle time
The DAM builds the zip before the download starts. Fifty originals came to 206 MB and about five minutes.
The numbers under every candidate

Five readings, printed in the order they matter.

All of them are measured against the original source and the run's reference, never a candidate's parent. The source's own lay score is printed beside each candidate so movement is visible at a glance.

LAYThe candidate's silhouette against the reference, normalised to the bounding box. The primary number.above 0.90Below about 0.90 the pose is still the source's. The prompt's pose section, or match_pose, is what moves it.
sizeThe garment's share of the frame over the reference's.1.01.4 means the candidate kept the source's framing. A redraw usually lands near 1.0.
flatSurface energy over the source's own.below 1A flat redraw sits at 0.4 to 0.5. Near or above 1 the creases survived. Far below 1 only matters if the construction went with them.
colour dE (hue)Colour difference read off the lit fabric of both garments. Judged on the hue part.hue under 4Under 4 is the same colourway. Over about 8 is a different one and disqualifies. Between the two, the lay decides.
same-garment IoUThe candidate against the source's silhouette.fallsIt drops when the lay changes, which is the job. High here with a low LAY means nothing moved. Below about 0.58 it is not the same object.

Two more checks arrive as text, not numbers: a lay check that compares the pose only, and a pins-and-labels read that says whether a sewn-in label, a logo or a seam went missing. A line marked ! means the numbers are not evidence for that candidate.

What the model can do

Sixteen tools, every one available every turn.

prompt_set, prompt_show
Write and check the prompt as named sections. Free.
generate
One fal.ai call per image, from the source or from any candidate. The only billed step, about 15 cents at 2K.
segment
Cut out a candidate too. The result is a cutout for measuring or generating from, never for shipping.
measure, compare_images, view_image
The numbers above, a side-by-side, a look. Free.
pick_best
The ranked list of what ships. Re-issue it as better ones arrive; the last call wins.
finish
Close the run with one of four honest statuses.
How a run ends

Exit codes say what to fix.

0

done, or budget exhausted

The best four are in output/ with picks.json and the model's LOG.md beside them.

1

something broke

A tool, the model server, or the search itself. Look at run.log in the run folder before looking at the garment.

20

no reference

The library holds nothing close enough, even after the text pull. Fix: add a suitable laydown, pass --reference, or give better --item-details text. Nothing was billed.

21

unclean source

The segmentation gate rejected the photo. Fix the input, not the model.

One run, one folder: runs/<session>/ holds the segmented source, the greyscale reference, every candidate with its measurements, the transcript, and run.log. References live flat in inputs/reference_library/; which files belong to which pull is in the manifests under dam_scraper/downloads/, not in the folder layout.
